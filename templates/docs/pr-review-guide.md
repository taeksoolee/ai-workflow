# PR 리뷰 가이드 (pr-review)

현재 브랜치의 PR 을 리뷰하고 결과를 정리·반영하는 절차를 정의한다.

## 호출 형태

```
/pr-review [PR 번호 또는 URL]
```

- 인자가 없으면 현재 브랜치에 연결된 PR 을 찾는다 (`gh pr view` 등).

## 절차

### 1. 변경 파악

- PR 의 제목·본문·커밋 목록·변경 파일을 조회한다.
- 변경의 의도를 한 문단으로 요약하고, 본문 설명과 실제 diff 가 일치하는지 확인한다.

### 2. 리뷰

아래 관점으로 diff 를 검토하고, 발견 사항을 심각도(치명/권장/참고)로 분류한다.

- **정확성:** 로직 오류, 경계 조건, 에러 처리 누락
- **스코프:** 요청 범위 밖의 변경이 섞여 있지 않은지 (`base.md` 스코프 규율)
- **일관성:** 기존 코드 스타일·컨벤션과의 정합
- **테스트:** 변경된 동작에 대응하는 테스트가 함께 고쳐졌는지

### 3. 결과 정리

- 발견 사항을 파일·라인 근거와 함께 목록으로 정리해 사용자에게 보여준다.
- 사용자가 동의한 항목만 반영한다: 코드 수정 또는 리뷰 코멘트 작성.
- **실제로 확인한 것과 추정인 것을 구분해 보고한다** (`base.md` 보고 정직성).
