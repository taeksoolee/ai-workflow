# AI 문서 초기화·재점검 가이드 (init-ai)

프로젝트를 분석해 루트 `AI.md` 의 PROJECT 슬롯을 채우고 필요한 절차 가이드를 제안하는 절차를 정의한다.
이미 채워진 프로젝트에서는 문서와 실제 상태의 어긋남을 찾는 재점검으로 동작한다.

## 호출 형태

```
/init-ai
```

## 모드 판별

`AI.md` 의 PROJECT 슬롯이 `<!-- PROJECT: ... -->` 주석 그대로면 **첫 채움 모드**,
하나라도 채워져 있으면 **재점검 모드**로 진행한다.

## 1. 프로젝트 분석 (공통)

다음을 순서대로 수집한다. 추측하지 말고 파일을 직접 읽는다.

1. **매니페스트·락파일** — 패키지 매니저, 주요 의존성(프레임워크·상태관리·테스트·빌드 도구), scripts 의 검증 명령
2. **기계 강제 장치** — 훅(.husky 등)·CI 워크플로우·린터 설정이 무엇을 검사하는지
3. **디렉토리 구조** — 최상위와 소스 루트의 구조 관례 (기능별/레이어별 분리, 테스트 위치 등)
4. **커밋 히스토리** — 최근 20개의 메시지 포맷·언어·prefix 관례 (base.md 기본 포맷과 다르면 기록 대상)
5. **기존 문서** — README, docs/, 이미 있는 `.ai-workflow/docs/*-guide.md`

## 2. 작성 원칙 (반드시 준수)

- **base.md 와 중복 금지.** 공통 규칙은 이미 `.ai-workflow/docs/base.md` 가 담당한다. AI.md 에는
  이 프로젝트에서만 참인 것만 적는다. base.md 기본값과 충돌하는 관례(예: 커밋 포맷)를 발견하면
  AI.md 에 명시한다 — 우선순위 규칙에 따라 AI.md 쪽이 이긴다.
- **기계가 강제하는 규칙은 옮겨 적지 않는다.** 훅·CI 가 검사하는 내용은 "정본은 `<설정 파일 경로>`" 로
  참조만 남긴다. 문서에 복제하면 둘이 갈리고 문서 쪽이 먼저 낡는다.
- **당위적 일반론 금지.** "깨끗한 코드를 쓴다" 류는 적지 않는다. 이 프로젝트에서 AI 가 실제로
  틀릴 지점(비직관적 구조, 함정, 반드시 거쳐야 하는 래퍼 등)만 적는다.
- **간결하게.** 슬롯당 몇 개의 불릿이면 충분하다. 여기 적히는 모든 줄은 이후 모든 에이전트
  세션의 컨텍스트 비용이다.

## 3. 제안 → 승인 → 기록 (첫 채움 모드)

1. 분석 결과를 슬롯별 초안으로 정리해 사용자에게 보여주고 승인을 받는다.
   **승인 전에는 어떤 파일도 수정하지 않는다** — 틀린 추론이 규칙으로 박제되는 것을 막는 안전장치다.
2. 승인받은 내용으로 `AI.md` 의 PROJECT 슬롯을 채운다.
3. 분석 중 반복 절차(릴리즈, 배포, 이슈 처리 등)를 발견했으면 `.ai-workflow/docs/<이름>-guide.md`
   신설을 제안한다. 만들 때는 이 문서처럼 상단에 skill frontmatter 를 선언한다.
4. 가이드를 추가했으면 `aiw setup` 실행을 안내한다 (도구별 래퍼 재생성).

## 4. 재점검 모드

1. `AI.md` 와 각 가이드의 주장을 실제 상태와 대조한다 — 검증 명령이 여전히 존재하는지,
   스택·구조 서술이 현재와 맞는지, 가이드 절차가 아직 유효한지.
2. 어긋남 목록(문서 주장 vs 실제)을 사용자에게 보여주고, 승인받은 항목만 갱신한다.
3. 더 이상 유효하지 않은 가이드는 삭제를 제안한다.

## 5. 마무리 (공통)

- 변경 사항을 요약해 보고하고, `aiw check` 로 상태를 확인한다.
